# Self-consistency vote share as a selective-classification signal

Code, per-call outputs and analysis for the paper

> O. N. M. Taher, H. A. Jeiad, F. A. Raheem, A. D. Salman, A. J. Humaidi. *Self-Consistency Vote Share as a Selective-Classification Signal for Zero-Shot LLM Text Classifiers.* Information (MDPI), manuscript information-4644612, under revision.

**Release:** tag `v2.0-revision`. The tag and the data tarball attached to that GitHub release are the versions the paper cites.

## What this repository studies

A zero-shot LLM classifier is called *k* times at temperature 0.7. The plurality label is the prediction (self-consistency), its vote share is the confidence, and the model abstains unless one label gets more than half of the *k* votes (a fixed strict-majority rule). The answered predictions are exactly those of self-consistency, so the question is whether the vote share, and abstaining below one half, is a useful confidence signal. The study compares it, on identical items, with single-call signals (label-set probability, answer-token probability, verbalized confidence), measures cost in generated tokens, and compares the fixed rule with risk-controlled (Learn-then-Test) thresholds and split-conformal sets.

Setup: AG News (7,600 items), DBpedia-14 (7,000), GoEmotions (5,427); Llama-3.2-3B-Instruct and DeepSeek-R1-Distill-Qwen-7B at *k* = 1, 3, 5 with three repeats; DeepSeek-R1-Distill-Qwen-32B and Llama-3.3-70B-Instruct on 2,000 items. vLLM 0.32.0, bf16.

## What the results say

* Extra calls lower calibration error in every condition (for example ECE 22.2% to 14.8% for the 7B model on AG News) and slightly raise the accuracy of the plurality label.
* The abstaining rule raises accuracy with abstentions counted as errors by 0.9 to 2.6 points on AG News and DBpedia, and lowers it on GoEmotions (about 2 points for the 7B model).
* Vote share is not generally a better error detector than single-call token probabilities, and it is nearly uninformative for the 70B model (AUROC 0.51 to 0.59).
* A near-greedy call (T = 0.01) is at least as accurate as voting at T = 0.7 for Llama.
* The fixed threshold carries no risk guarantee; where vote share is informative, a calibrated threshold is preferable.

Tables are in `results/` and are regenerated by `revision/analyze_unified.py`.

## Quickstart

```bash
git clone https://github.com/Akramtaha98/llm_majority_vote_ollama && cd llm_majority_vote_ollama
git checkout v2.0-revision
bash revision/setup.sh                       # venv, vLLM 0.32.0, model downloads
bash revision/launch_all.sh                  # 4 GPU workers (tmux); watch bash revision/monitor.sh
python revision/analyze_unified.py --runs runs/unified --out results/tables_main --boot 2000
```

Full protocol, file list and commands: [`revision/README.md`](revision/README.md). No GPU is needed to check the analysis code (`revision/make_synthetic.py`).

## Data

* **Result tables** (small, in git): `results/tables_main`, `results/tables_32b`, `results/tables_70b`.
* **Per-call outputs** (parsed labels, generated-token counts, truncation flags, answer-token probabilities, label-set probabilities for every run): `unified_runs_v2.0-revision.tar.gz`, attached to the GitHub release with a SHA-256 file. Unpack at the repository root to get `runs/unified*`.
* The datasets are public: AG News (`fancyzhx/ag_news`), DBpedia-14 (`fancyzhx/dbpedia_14`), GoEmotions simplified.

## Repository layout

| Path | Content |
|---|---|
| `revision/` | the pipeline behind the paper (runner, job queue, analysis, release packaging) |
| `results/` | result tables of the paper |
| `src/llm_vote/` | dataset loaders (`datasets.py`), prompt builder, label parsing and vote counting (`voter.py`), metrics, clients |
| `archive/` | the first version of the study (Ollama, Q4_K_M), kept for provenance only; none of it is used in the paper |
| `runs/`, `vote_records/`, `outputs/`, `out_figs/`, `scripts/`, `data/` | records and scripts of the first version (see `archive/README_first_version.md`) |

The first-version records predate the unified protocol: they used Ollama with Q4_K_M quantisation, different sample sizes and, for some AG News conditions, an unshuffled first-N slice. They are not comparable with the paper's numbers and are not cited.
